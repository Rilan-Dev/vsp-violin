   101→01
   102→What makes a premium animated site
   103→Why generic AI output looks cheap even when the code is technically competent.
   104→Premium work is not defined by the number of effects. It is defined by control. A high-end hero usually has a clear focal subject,
   105→deliberate negative space, intentional typography, a restrained material language and a motion narrative that helps the
   106→experience progress rather than merely decorate it.
   107→THE GENERIC AI PATTERN THE PREMIUM PATTERN
   108→Centered headline. Gradient background. Floating glass Art direction first. Bespoke assets. Strong hierarchy.
   109→cards. Generic pill buttons. Random fade-ups. Stock-like Purposeful interactions. Exact responsive states.
   110→imagery. Desktop-first layout with mobile treated as a Measurable motion beats. Consistent materials. Clean
   111→scale-down. implementation and validation.
   112→The seven levers of perceived value
   113→• Art direction - a coherent visual thesis that can be described in one sentence.
   114→• Asset control - custom subjects, environments, transparent layers, frames and shells instead of placeholder graphics.
   115→• Composition - focal point and copy occupy deliberately different territories.
   116→• Typography - hierarchy, line breaks, tracking and rhythm are treated as design, not defaults.
   117→• Motion - state changes are timed and mapped to a narrative.
   118→• Responsiveness - desktop, tablet and mobile are composed as distinct states.
   119→• Implementation precision - the browser reproduces the intended values instead of letting a model "make it similar."
   120→RULE OF THUMB
   121→If you can remove the hero image, swap the palette and rename the brand without changing the structure, you probably have a
   122→generic template - not an art-directed experience.

   174→Remix inspiration into an original direction
   175→Turn a pile of references into a single authored visual system.
   176→Before generation or coding, write a one-page art-direction brief. The brief forces you to decide what belongs together and what
   177→does not. It is the filter that stops the project becoming a collage of unrelated references.
   178→DECISION EXAMPLE QUESTIONS
   179→Identity What is the brand trying to feel like: clinical, brutalist, cinematic, playful, technical, editorial?
   180→Palette How many accent colors exist? Which one carries signal and which ones stay neutral?
   181→Type What is display versus interface versus technical copy?
   182→Geometry Soft radii, sharp chamfers, circular cutouts, thin technical frames, full bleed?
   183→Photography Where is the subject? Which direction do they face? What light and lens language?
   184→Motion personality Elastic, mechanical, cinematic, editorial, high-frequency HUD, slow luxury?
   185→Interaction What does the pointer reveal, what does scroll advance, what opens on click?
   186→A useful remix method is: Collect -> Deconstruct -> Select -> Transform -> Recombine -> Art-direct. If the result still looks like
   187→the original reference with a different logo, the transformation step was too weak.
   188→YOUR TASTE IS THE CONTROL LAYER
   189→AI can produce options at speed. It cannot decide which compromises are acceptable for your brand unless you teach the system
   190→what matters. Your job is selection, rejection and correction.

   200→Set up the AI creative studio with MCP
   201→Use an agent as the production console, then connect specialist media tools for generation and
   202→iteration.
   203→Model Context Protocol (MCP) lets a compatible AI client call external tools inside the same working session. For a creative
   204→workflow, that means the conversation can move from art direction to image generation, refinement, video generation and
   205→implementation without repeatedly rebuilding context.
   206→Magnific MCP - current setup
   207→1 Open your MCP-compatible client and go to its Connectors/Apps area.
   208→2 Add Magnific from the connector directory where available, or add the endpoint manually: https://mcp.magnific.com
   209→3 Authenticate with your Magnific account and approve the requested permissions.
   210→4 Ask the agent to generate, edit, relight or upscale an asset, then iterate on the same selected result instead of restarting
   211→from zero.
   212→CURRENT PRODUCT NOTE
   213→Magnific states that MCP is available on paid plans and MCP actions consume credits. Its documentation lists Claude, ChatGPT,
   214→Cursor, Codex, VS Code, Gemini and other compatible clients. Verify the latest plan/UI before publishing a tutorial because
   215→connector menus can change.
   216→Higgsfield MCP / CLI - current setup
   217→1 For MCP, add a custom connector named Higgsfield with: https://mcp.higgsfield.ai/mcp
   218→2 Authenticate through your Higgsfield account. The official MCP flow does not require a separate API key.
   219→3 For Claude Code or other terminal-first workflows, the current CLI path is: npm i -g @higgsfield/cli, then higgsfield auth
   220→login, then npx skills add higgsfield-ai/skills.
   221→4 Use prior generations as references so the agent can refine or animate a selected asset rather than generating
   222→disconnected variants.
   223→CHATGPT AVAILABILITY
   224→Full custom MCP/app support in ChatGPT is plan/workspace dependent and continues to evolve. As of Aug 2026, OpenAI
   225→documents full MCP support for Business and Enterprise/Edu on web. If a client cannot add the connector, use a supported MCP
   226→client such as Claude/Claude Code, Cursor, Codex or another compatible environment.

   250→PART II - ASSETS & MOTION
   251→05
   252→Engineer assets before code
   253→The strongest AI sites are designed around controlled visual inputs, not code-generated
   254→placeholders.
   255→Treat every critical hero asset as production material. Decide what role it plays in the DOM, what crop it needs, which areas
   256→must remain quiet for copy, whether transparency is required and whether a separate mobile treatment is necessary.
   257→ASSET TYPE ENGINEERING QUESTION
   258→Hero background Where is the focal subject? Is the copy area protected? Does mobile need a different crop?
   259→Character / product layer Does it need alpha? What is its center axis? What must never be mirrored or regenerated?
   260→Poster frame Does it match the first video frame and prevent a black flash?
   261→Shell / frame artwork Will live HTML sit on top? Must the asset stretch, fill, mask or clip inside a fixed box?
   262→Texture / ornament Can it be procedural CSS/SVG instead of another request?
   263→Video clip Is it designed for autoplay, normal playback or currentTime scrubbing?
   264→Asset acceptance checklist
   265→• Composition matches the intended website role, not merely a pretty standalone image.
   266→• Subject orientation is correct and leaves deliberate negative space.
   267→• Face/product identity survives enhancement and animation.
   268→• Transparency edges are clean and not haloed.
   269→• Lighting direction and color temperature match adjacent assets.
   270→• Desktop and mobile crops have been tested in a browser-shaped frame.
   271→• No unlicensed font, logo, stock image or proprietary visual is being redistributed.

   279→PART II - ASSETS & MOTION
   280→06
   281→Prompt visual assets precisely
   282→Structure prompts like a production specification rather than an adjective pile.
   283→A useful prompt is hierarchical. Put identity and composition first because those are the expensive things to correct later.
   284→Lighting, materials and texture come after the image is structurally right.
   285→IDENTITY
   286→Exact subject / product / role.
   287→COMPOSITION
   288→Placement, orientation, negative space, crop, aspect ratio.
   289→CAMERA
   290→Framing, lens feel, perspective, camera height.
   291→LIGHTING
   292→Direction, softness, key/fill/rim, color temperature.
   293→MATERIALS
   294→Surface behavior: matte ceramic, brushed metal, real skin, leather, glass.
   295→WEBSITE ROLE
   296→Hero background, transparent foreground layer, card image, poster, etc.
   297→PRESERVE
   298→Elements that may not move or change.
   299→DO NOT
   300→Specific failure modes: no mirrored subject, no extra jewelry, no text, no oversharpening.
   301→Iteration discipline
   302→Do not rewrite the entire prompt after every defect. If composition is correct and texture is wrong, preserve composition and
   303→correct texture. If identity is correct and the subject is facing the wrong direction, fix orientation without reopening color,
   304→clothing and environment. Iteration becomes faster when each pass has one job.
   305→PROMPTING IS NOT THE SAME AS ART DIRECTION
   306→The prompt describes constraints. Art direction is the judgment that decides which constraints matter, which generation is usable
   307→and what must be rejected.

   316→07
   317→Refine without destroying the asset
   318→Use Magnific or another enhancer as a controlled finishing pass, not a creative reset.
   319→Enhancement should increase believability while preserving the approved composition. The common failure is an enhancer that
   320→makes the image superficially sharper but changes the face, invents texture or pushes everything into synthetic CGI crispness.
   321→1 Lock the composition first. Do not enhance a structurally wrong image.
   322→2 Identify a measurable defect: skin texture, material micro-detail, edge quality, lighting realism, local blur or aliasing.
   323→3 Use a conservative refinement pass with explicit preservation instructions.
   324→4 Compare against the approved source at the same crop. Check face, silhouette, negative space and object position before
   325→checking detail.
   326→5 Reject overprocessed outputs. A more detailed image is not automatically a more realistic image.
   327→CHECK FAILURE SIGNAL
   328→Identity Face shape, eyes, hairstyle or product silhouette changed
   329→Composition Crop, camera height or subject position drifted
   330→Texture Skin turns waxy; metal becomes plastic; wood becomes noise
   331→Edges Transparent edges halo or gain unwanted sharpening
   332→Lighting Rim/key direction changes and no longer matches the scene
   333→Detail Fake micro-text, random seams, invented hardware or excessive pores

   342→08
   343→Turn stills into motion
   344→Animate the state change the website needs, not a generic cinematic shot.
   345→A website motion asset is constrained by the UI. If the hero needs copy on the left, the video must protect that space
   346→throughout the transition. If the scroll story ends on a different visual state, the final frame must land where the UI expects it.
   347→USE CASE MOTION BRIEF
   348→Subtle living hero Micro head/eye/environment motion; camera largely locked; seamless visual continuity
   349→Scroll-scrub transformation Clear chronological state change with stable subject identity and no sudden camera cuts
   350→Character reveal Preserve center axis; transition only the intended layer or pose
   351→Product hero Controlled orbit or material reveal; no framing drift that breaks overlay UI
   352→Green-screen / keyed asset Consistent subject, clean background, no spill on edges, minimal camera translation
   353→Example Higgsfield-style direction
   354→Use the approved reference image as the identity and composition anchor.
   355→Keep the camera nearly locked. Preserve the subject on the right third for the entire clip.
   356→Animate a restrained 6-second progression: neutral gaze -> subtle light activation -> controlled
   357→head/eye movement -> final resolved state.
   358→Do not change clothing, face, lens perspective, background layout or aspect ratio.
   359→No hard cuts. No text. No extra objects. The final frame must remain compatible with left-aligned
   360→hero copy.
   361→FIRST/LAST FRAME THINKING
   362→Before generating motion, define what frame 0 and the final frame must accomplish for the interface. This makes the video an asset
   363→in a system, not a standalone clip.

   372→09
   373→Design the motion system before coding
   374→Map states, transitions and interface reactions onto normalized progress.
   375→Premium motion feels intentional because multiple layers respond to the same narrative. A pinned hero can treat scroll as a
   376→normalized timeline from 0 to 1, then map video time, copy, theme, cards, navigation and progress UI to that shared progress.
   377→0.00 0.20 0.50 0.78 1.00
   378→ARRIVAL ---- REVEAL ---- TRANSFORM ---- PROOF/CARDS ---- RESOLUTION
   379→| | | | |
   380→video copy out theme shift cards in handoff
   381→copy 1 copy 2 proof in CTA in nav state
   382→Do not start by asking, "What animations can I add?" Start by asking, "What state is the user in now, what state comes next, and
   383→what should visually communicate that transition?"
   384→• Use one source of truth for scroll progress where possible.
   385→• Define transition windows before tuning easing.
   386→• Keep the number of simultaneous hero systems understandable.
   387→• Avoid animation that fights the focal subject or moves copy across the face/product.
   388→• Design the final unpin/handoff state so the page does not feel like it simply stops.

   396→PART III - IMPLEMENTATION
   397→10
   398→Build with GSAP and the right animation layer
   399→Use the simplest system that can reproduce the choreography precisely.
   400→CSS transitions and keyframes are excellent for deterministic micro-motion. GSAP becomes valuable when several elements
   401→need coordinated timelines, precise control, pointer smoothing or scroll-linked state. ScrollTrigger supports trigger-based
   402→animation, pinning and scrubbed timelines; its numeric scrub option adds catch-up smoothing between scrollbar and playhead.
   403→PROBLEM GOOD DEFAULT
   404→Simple hover / focus / loader pulse CSS transition or keyframes
   405→Component state animation CSS or a framework motion layer
   406→Complex timeline choreography GSAP Timeline
   407→Pinned scroll narrative GSAP ScrollTrigger
   408→Smooth pointer following GSAP quickTo / ticker
   409→3D rendering requirement Three.js/WebGL only if the design genuinely needs a renderer
   410→Scroll architecture pattern
   411→gsap.registerPlugin(ScrollTrigger)
   412→const tl = gsap.timeline({
   413→scrollTrigger: {
   414→trigger: hero,
   415→start: "top top",
   416→end: () => "+=" + window.innerHeight * N,
   417→pin: true,
   418→scrub: 1,
   419→invalidateOnRefresh: true
   420→}
   421→})
   422→// Add state transitions to the timeline.
   423→// Clean up the GSAP context / trigger on unmount.
   424→DO NOT ANIMATE THE PINNED CONTAINER BLINDLY
   425→Pin geometry is measurement-sensitive. Animate children inside the pinned area unless you understand how transforming the
   426→pinned element affects ScrollTrigger calculations.

   434→PART III - IMPLEMENTATION
   435→11
   436→Use SVG, shells, masks and hybrid controls
   437→Premium controls often combine authored artwork with live semantic HTML.
   438→A button does not have to be either an image or CSS. A strong hybrid control can use a transparent generated shell underneath a
   439→live label and live SVG arrow. The shell provides the unique material treatment; HTML preserves accessibility, responsive
   440→typography and interaction.
   441→BUTTON / CARD STACK
   442→1. Supplied shell / frame artwork
   443→2. Image or material layer
   444→3. Directional fade / readability mask
   445→4. Sheen / highlight
   446→5. Rim / border / SVG outline
   447→6. Live HTML content + semantic control
   448→7. GSAP/CSS interaction state
   449→• Keep exact SVG viewBox and path data when the geometry is part of the design.
   450→• Do not replace a measured chamfer with a generic rounded rectangle.
   451→• Use masks/clip-paths when reveal geometry is interaction-critical.
   452→• Keep live labels out of raster assets when they need to remain accessible and responsive.
   453→• If a supplied shell intentionally uses object-fit: fill inside a fixed box, do not "correct" it to contain.
   454→WHY THIS MATTERS
   455→When a coding model hears "make a luxury glass button," it invents a new design. When it receives the actual shell plus exact
   456→HTML/SVG structure, visual inference drops dramatically.

   466→Treat responsive as art direction
   467→Mobile is a different composition, not desktop squeezed into less width.
   468→Responsive fidelity is one of the fastest ways to tell whether a premium site is truly designed. The focal subject, copy block,
   469→controls and motion density often need different rules across desktop, tablet and mobile.
   470→STATE DECISIONS TO LOCK
   471→Large desktop Max clamps, media quality, copy width, decoration density, wide nav
   472→Desktop Fluid spacing, focal point, pointer behavior, pin distance
   473→Tablet Desktop vs mobile motion branch, crop changes, control visibility
   474→Mobile Different media/crop, copy anchoring, simplified HUD, card scroller
   475→Short height What compresses? What must stay visible? Does the source intentionally have no height breakpoint?
   476→Test both sides of every meaningful breakpoint. If 768 is desktop and 767 is mobile, validate both. If 640 is a hybrid state and
   477→639 is compact mobile, validate both. A one-pixel boundary can change source selection, control visibility or motion architecture.
   478→THE FOCAL-POINT TEST
   479→At every viewport, draw an imaginary exclusion zone around the face/product. Important copy and controls should not collide with
   480→it unless the art direction explicitly intends that overlap.

   489→13
   490→Run a disciplined polish loop
   491→Iteration is part of premium work. The goal is controlled convergence, not endless tweaking.
   492→A useful review loop is visual and measurable. Capture the site at a fixed viewport, compare it with the intended state, identify
   493→the largest mismatch and change only the subsystem that caused it.
   494→1 Capture the exact viewport and state.
   495→2 List mismatches by category: geometry, asset, type, color, motion, interaction, responsive, network.
   496→3 Choose the highest-impact mismatch. Do not change five systems at once.
   497→4 Implement a narrow correction.
   498→5 Re-run the same viewport/state and compare again.
   499→6 Only after visual parity, run console/network/build checks.
   500→PASS QUESTIONS
   501→Visual Are subject position, scale, crop, layers, type and gradients correct?
   502→Motion Are state windows, delays, eases and scrub behavior correct?
   503→Interaction Do menu, cursor, hover, CTA and keyboard states behave correctly?
   504→Responsive Are breakpoint branches and mobile media correct?
   505→Technical No console warnings, 404s, rejected promises, overflow or build failures?
